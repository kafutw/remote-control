# 「看注音寫字」交接文件

要接手的人看這一份就夠。試做頁在 `write-demo.html`，可以直接開：
<https://kafutw.github.io/remote-control/write-demo.html>

---

## 一、這是什麼

`chinese.html`（國語大考驗）現在所有題型都是**四選一**。這個功能要補的是**真的動手寫**——
看注音，在田字格裡用手指把字寫出來。

出題長這樣（**只給注音不行**，ㄏㄨㄚ 可以是 花／華／化／畫，看不出要寫哪個，
所以一定要有語詞當線索）：

```
      ㄏㄨㄚ
      ＿朵
```

---

## 二、兩種判斷方式，試做都做了

### A. 自動比對（**建議走這條**）

拿**楷體字型畫出來的字當標準答案**，跟小孩寫的線互相比。兩個指標：

| 指標 | 怎麼算 | 抓得到什麼 |
|---|---|---|
| **覆蓋率** | 這個字該有的地方，他寫到了幾成 | 漏筆、寫太小、位置偏掉 |
| **乾淨度** | 他寫的線，有幾成落在這個字上面 | 多寫、寫到格子外面 |

再加一條硬規定：**筆畫數要跟教育部辭典的總筆畫一樣**（`DICT` 裡本來就有，查表即可）。

實測（把標準筆畫餵進去當「寫得很好」，再故意加工）：

| 情況 | 覆蓋率 | 乾淨度 | 抓到了嗎 |
|---|---|---|---|
| 照標準寫 | 89% | 100% | ⭕ 過 |
| 手抖一點 | 91% | 100% | ⭕ 過 |
| **多兩撇**（實際遇到的） | 89% | **89%** | ✗ 乾淨度掉下來 + 筆畫數多 2 |
| 少一筆 | 84% | 100% | ✗ 靠筆畫數抓 |
| 少三筆 | **59%** | 100% | ✗ 覆蓋率直接掉 |
| 整個往右偏 35px | **68%** | 91% | ✗ 覆蓋率掉 |
| 寫成別的字 | 78% | 86% | ✗ 兩個都掉 + 筆畫數不對 |

**成本 0**：字型本來就在裝置上，筆畫數本來就在 `DICT` 裡。不需要任何外部資料。

技術細節（都在 `write-demo.html` 的 `compare()` 附近）：
- 兩張 128×128 的黑白圖，一張是字型填實的字，一張是小孩的線
- 兩趟 chamfer 距離轉換算「離最近的黑點多遠」，容差約 7 格（手寫抖動不計較）
- 128×128 = 16k 像素，手機上跑起來無感

### B. 逐筆對筆順（**先不要做，見第三節**）

每寫一筆就跟正確筆順比：把兩條線都重新取樣成等距 16 點，逐點比距離
（容差 11.5% 格寬），再比方向和長度。錯了會說「第 3 筆方向反了」，
對了就把**標準的那一筆**收進去，所以寫完是漂亮的字。

程式碼可以用（`checkStroke()`），**卡在資料**。

## 三、⚠️ 最重要的一件事：筆順資料的來源不能用

試做用的是 [`skishore/makemeahanzi`](https://github.com/skishore/makemeahanzi)。
拿它的筆畫數跟教育部辭典逐字對，**2,246 個字裡有 276 個對不起來（12.3%）**：

```
差 +1 畫：248 個   差 +2：7 個   差 -1：18 個   差 -2：1 個   差 -3：2 個
例：之 3/4、以 4/5、及 3/4、似 6/7、修 9/10、健 10/11、初 7/8、印 5/6
    花 7/8、草 9/10
```

原因是**那份資料是大陸的筆畫標準**。最典型的是「艹」：大陸算 3 畫、台灣算 4 畫，
所以 花、草 全部差 1。

**後果**：如果照它教筆順，小孩在學校會被算錯，而且會跟 App 自己的
「✏️ 數筆畫」題目打架（那題用的是教育部的數字）——同一個 App 說 草 是 10 畫，
寫字練習卻只讓你寫 9 筆。

**所以：B 方案要做的話，必須先找到台灣標準的筆順資料。**
可以找的方向：教育部《國字標準字體筆順學習網》、《常用國字標準字體筆順手冊》。
找不到就只做 A。

## 四、要併進 `chinese.html` 的話

1. 加一個題型 `write`，跟現有的 `ZI_KINDS` 並排（`chinese.html` 的 `KIND_LABEL` 附近）
2. 題目用「注音 + 挖空的語詞」——`itemOf(c)` 裡的 `words` 已經有語詞可以挖
3. 作答畫面換成田字格 canvas，不是四個選項
4. 判對錯用 A 方案的 `compare()`，門檻建議覆蓋率 80%、乾淨度 80%、筆畫數要一致
5. 結果照樣丟進 `logRecent(c, ok)`，熟練度、課的獎牌、首頁的每日獎牌都會自動吃到
6. 一輪的題數／秒數要重新想——寫字比選擇題慢很多，20 題大概太多

### 已知還沒解的

- **字型不一定有**：`--abc` 那串楷體在 iOS/Mac 有（BiauKai），Android 常常沒有，
  會退到黑體，比對的標準答案就會是黑體的形狀。要嘛內嵌字型（大）、要嘛偵測不到就
  只給「自己對答案」。**這條沒驗證過，要先測 Android。**
- 小孩寫得很小或很偏的時候，要不要先正規化到田字格再比？現在沒有正規化，
  所以「寫太小」會被判沒寫到。這樣對不對要問家長。
- 沒有處理連筆（兩筆黏在一起畫成一筆）——筆畫數會少 1。

## 五、檔案

| 檔案 | 是什麼 |

直接寫死在檔案裡（`var STROKES`）。

## 六、如果決定要全部字的筆順資料，體積是這樣

| 方案 | 原始 | gzip |
|---|---|---|
| 完整外框路徑 | 5.17 MB | 2.03 MB |
| 完整外框、座標降到 256 格 | 4.78 MB | 1.63 MB |
| 只要骨架（筆順動畫＋逐筆判斷夠用） | 1.41 MB | 0.53 MB |
| 骨架、座標降到 128 格 | 1.16 MB | 0.35 MB |
| 現在的 `chinese.html` | 0.29 MB | 0.11 MB |

注意 `chinese.html` **每次開啟都會重抓自己一次比對版本**（`VERSION` 那段），
所以檔案變大是每次開都要付的成本。真要做，建議**只載入選到那一課的字**
（一課 16 個字約 7 KB），不要整包塞進去。
