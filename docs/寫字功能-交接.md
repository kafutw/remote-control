# 「看注音寫字」交接文件

要接手的人看這一份就夠。試做頁在 `write-demo.html`，可以直接開：
<https://kafutw.github.io/remote-control/write-demo.html>

---

## 一、這是什麼

`chinese.html`（國語大考驗）現在所有題型都是**四選一**。這個功能要補的是**真的動手寫**——
看注音，在田字格裡用手指把字寫出來。

出題長這樣（**只給注音不行**，ㄏㄨㄚ 可以是 花／華／化／畫，看不出要寫哪個，
所以一定要有語詞當線索）：

```
      ㄏㄨㄚ
      ＿朵
```

## 二、兩種判斷方式，試做都做了

### A. 自動比對（**建議走這條**）

拿**楷體字型畫出來的字當標準答案**，跟小孩寫的線互相比。兩個指標：

| 指標 | 怎麼算 | 抓得到什麼 |
|---|---|---|
| **覆蓋率** | 這個字該有的地方，他寫到了幾成 | 漏筆、寫太小、位置偏掉 |
| **乾淨度** | 他寫的線，有幾成落在這個字上面 | 多寫、寫到格子外面 |

再加一條硬規定：**筆畫數要跟教育部辭典的總筆畫一樣**（`DICT` 裡本來就有，查表即可）。

實測（把標準筆畫餵進去當「寫得很好」，再故意加工）：

| 情況 | 覆蓋率 | 乾淨度 | 抓到了嗎 |
|---|---|---|---|
| 照標準寫 | 89% | 100% | ⭕ 過 |
| 手抖一點 | 91% | 100% | ⭕ 過 |
| **多兩撇**（實際遇到的） | 89% | **89%** | ✗ 乾淨度掉下來 + 筆畫數多 2 |
| 少一筆 | 84% | 100% | ✗ 靠筆畫數抓 |
| 少三筆 | **59%** | 100% | ✗ 覆蓋率直接掉 |
| 整個往右偏 35px | **68%** | 91% | ✗ 覆蓋率掉 |
| 寫成別的字 | 78% | 86% | ✗ 兩個都掉 + 筆畫數不對 |

**成本 0**：字型本來就在裝置上，筆畫數本來就在 `DICT` 裡。不需要任何外部資料。

技術細節（都在 `write-demo.html` 的 `compare()` 附近）：
- 兩張 128×128 的黑白圖，一張是字型填實的字，一張是小孩的線
- 兩趟 chamfer 距離轉換算「離最近的黑點多遠」，容差約 7 格（手寫抖動不計較）
- 128×128 = 16k 像素，手機上跑起來無感

### B. 逐筆對筆順（**入口已從試做頁移除，見第三節**）

每寫一筆就跟正確筆順比：把兩條線都重新取樣成等距 16 點，逐點比距離
（容差 11.5% 格寬），再比方向和長度。錯了會說「第 3 筆方向反了」，
對了就把**標準的那一筆**收進去，所以寫完是漂亮的字。

程式碼可以用（`checkStroke()`、`playOrder()`），**卡在資料**。

> **2026-08-21 更新**：試做頁上「逐筆看筆順」模式和「👀 看筆順」動畫這兩個入口
> 已經拿掉，因為它們會照大陸筆順教。函式和 `STROKES` 都留在檔案裡（有警語注解），
> 拿到台灣標準的資料換掉 `STROKES` 就能接回來。**在那之前不要把入口打開。**

## 三、⚠️ 最重要的一件事：筆順資料的來源不能用

試做用的是 [`skishore/makemeahanzi`](https://github.com/skishore/makemeahanzi)。
拿它的筆畫數跟教育部辭典逐字對，**2,246 個字裡有 276 個對不起來（12.3%）**：

```
差 +1 畫：248 個   差 +2：7 個   差 -1：18 個   差 -2：1 個   差 -3：2 個
例：之 3/4、以 4/5、及 3/4、似 6/7、修 9/10、健 10/11、初 7/8、印 5/6
    花 7/8、草 9/10
```

原因是**那份資料是大陸的筆畫標準**。最典型的是「艹」：大陸算 3 畫、台灣算 4 畫，
所以 花、草 全部差 1。

**後果**：如果照它教筆順，小孩在學校會被算錯，而且會跟 App 自己的
「✏️ 數筆畫」題目打架（那題用的是教育部的數字）——同一個 App 說 草 是 10 畫，
寫字練習卻只讓你寫 9 筆。

**所以：B 方案要做的話，必須先找到台灣標準的筆順資料。**

### ✅ 2026-08-21：找到了，但只有一半

**全字庫（CNS11643）** 有台灣標準的筆順資料，授權是政府資料開放授權條款第一版（可商用）。
已經抓下來放在 `data/台灣筆順_全字庫.txt`，查證與授權標示寫在
`data/台灣筆順_全字庫_說明.md`。

拿 `DICT` 的 2,257 字逐字對：

| | 全字庫 | 原本的 makemeahanzi |
|---|---|---|
| 查得到 | 2257 / 2257（100%） | — |
| 筆畫數對不上教育部 | **5 字（0.22%）** | **276 字（12.3%）** |
| 花 / 草 | ✅ 8 / 10（正確） | ✗ 7 / 9 |
| 體積（全部字） | 34 KB／gzip **13 KB** | 骨架版 1.41 MB／gzip 0.53 MB |

**但它是筆畫「類型」序列，不是座標**（1=橫 2=豎 3=撇 4=點 5=折）。所以：

- ✅ 做得到：判斷每一筆的類型和順序 →「第 3 筆應該是橫，你寫成豎了」
- ✗ 做不到：筆順動畫（沒有幾何）、逐筆位置比對（原本的 `checkStroke()` 要重寫）

要動畫就得回去找有座標的資料，而目前找得到有座標的都是大陸標準。

### ✅ 2026-08-21：已經實作並上線

`strokeType()` 從軌跡反推筆畫類型，`orderProblem()` 跟正確序列比、回報第一個錯的位置。

**先驗過兩個容易搞錯的字**：教育部的「左」「右」**都是橫開頭**（不是坊間說的
「左先橫、右先撇」），全字庫的 `13121` / `13251` 完全正確。動手前查了官網動畫確認。

**辨識準確率**（拿真實筆畫幾何加雜訊模擬手寫，各跑 40 輪）：

| 手抖程度 | 誤報（寫對卻說錯） | 抓到（真的寫錯順序） |
|---|---|---|
| 無 | 0% | 90% |
| 小（±2.8px） | 0.6% | 92% |
| 中（±5.6px） | **1.9%** | **88%** |
| 大（±10px） | 16% | 82% |

關鍵在**「認不準就不出聲」**（`strokeType()` 回傳的 `sure`）。沒有這道閘門的話，
中度手抖就有 14% 的整字誤報——那比不做還糟。

**做的過程踩到兩個坑**，都寫在程式碼註解裡：
1. 沒有平滑處理的話，手抖製造的假轉角會把幾乎所有筆畫都判成「折」
2. 彎撇和豎彎鉤都是漸進彎曲，要靠「往左收 vs 往右收」才分得開

**接到難度開關上**：輕鬆＝不看筆順、標準＝只提示、嚴格＝筆順錯就不算過。
預設「標準」，因為 2% 的誤報不該讓孩子被判不過。

### 逐筆檢查（2026-08-21 加回來）

「照筆順寫」模式現在會**邊寫邊檢查**：每寫一筆就認它的類型，跟正確序列比，
錯了直接退回去重寫，格子底下還會顯示「接下來要寫 ⟨橫⟩」。

這一段原本以為要座標才做得到，其實不用——認類型就夠了。
`endStroke()` 裡那段，認不準（`sure` 是 false）的筆畫一律默默收下，不冤枉人。

**筆順示範動畫還是回不來**，那真的需要每一筆的座標，全字庫只給類型序列。

## 三之二、寫錯的時候不給「換一題」（2026-08-21 加）

小孩寫錯只會看到一顆「✏️ 再寫一次」，沒有跳過的按鈕。判定分三檔：

| 檔 | 條件 | 畫面 |
|---|---|---|
| 過 | 三項門檻都到 | 出現「換一題」 |
| **差一點** | 差在門檻附近（覆蓋率、乾淨度各差 12 個百分點以內，筆畫多容忍 1 筆） | 「再寫一次」＋「差一點點」標籤，家長通道那行字轉成琥珀色 |
| 不對 | 其他 | 「再寫一次」，家長通道維持灰色小字 |

**門檻可調**（`LEVELS`，頁尾有開關，存 `localStorage` 的 `writeDemoLevel`）：

| 難度 | 覆蓋率 | 乾淨度 | 筆畫數 |
|---|---|---|---|
| 輕鬆 | 60% | 55% | 差 1 筆也算過 |
| **標準**（預設） | 70% | 65% | 要正確 |
| 嚴格 | 80% | 78% | 要正確 |

原本寫死 80/80 太嚴：實測一個寫得很好的「左」是 82% / 78% / 筆畫 5-5，
只因為乾淨度差 2 分就被判不過。用手指在大格子裡寫，超出筆畫邊緣是常態。

併進 `chinese.html` 時**這個開關要搬進設定頁**，不要留在練習畫面上。

**家長／老師通道**：判定卡底下一行小字，點下去跳出面板，先看他寫的字和三個數字，
再答一題就能放行（「算他過，下一題」／「不算，讓他重寫」）。

**只有這一道關卡，沒有密碼、沒有設定、不存任何東西**（整支 `write-demo.html` 不碰
`localStorage`）。所以每一台平板、每一支手機、每一個瀏覽器行為都一模一樣，
換裝置不用重設，也不必把任何數字寫進這個公開 repo。

**題庫**（`adultQ()`，數字每次隨機）：

| 題型 | 例 | 為什麼一年級不會 |
|---|---|---|
| 平方 | `7 的平方是多少？` → 49 | 沒有平方的概念 |

只出 2–9 的平方，答案是 4、9、16、25、36、49、64、81，大人一眼就有。
原本還有面積題和時間換算題，實測「邊長 10 公分的正方形」這種太累，砍掉了。

答錯就換一題新的。輸入用面板裡自己畫的數字鍵盤（`buildKeypad()`），
不叫系統鍵盤——iPad 橫式叫出來會吃掉大半個畫面。

四種被否決的做法，都是同一個道理（可猜、可背、或要各自設定）：

| 做法 | 為什麼不行 |
|---|---|
| 選擇題 | 四選一又能無限重試，亂點平均四次就過 |
| 分子分母 | 答案就印在題目上，兩個數字亂猜一半會中 |
| 固定答案（三角形內角和永遠 180） | 小孩看大人按一次就記住 |
| 四位數金鑰 | 固定的、看幾次就背起來，而且每台裝置要各設一次，不通用 |

**純九九乘法也不用**：隔壁 `multiplication.html` 就在練那個，背熟就破了。

**卡關保護**：同一題連錯 3 次，描紅自動打開，家長通道那行字換成
「寫好幾次了？家長／老師可以看一下 →」。還是不給自己跳過。

程式在 `write-demo.html` 的 `openGate()` 一帶，`adultPassed` 陣列先記在記憶體裡。

## 三之三、版型與田字格大小（2026-08-21 加）

田字格改成自適應（`--padmax`），寬度吃滿容器，再被「畫面剩多少高」和上限夾住。
**橫式（iPad 橫拿＋電腦）是主要使用情境，所以書寫空間優先，題目卡壓小讓位：**

| | 原本 | 現在（實測） |
|---|---|---|
| iPad 直式 768×1024 | 280px | **513px** |
| iPad 橫式 1194×790 | 330px | **594px** |
| 筆電 1440×900 | — | **630px** |
| 桌機 1900×1100 | — | **830px** |

**大螢幕另外有一段規則**（`min-width:1280px`）：內容跟著放大並**垂直置中**
（`align-content:center` ＋ `min-height`），字級、卡片內距、按鈕全部往上調，
田字格上限從 760 拉到 900。沒有這一段的話，桌機上會變成一小塊擠在畫面上方、
下面一大片空白。課次維持兩欄——三欄會讓「大個子，小個子」這種長課名折行。

橫式為了讓出高度做了這些：首頁副標隱藏、標題縮小、題目卡的注音和語詞縮小、提示句隱藏。

**所有可調的東西都收在右上角的齒輪裡**（`#gearBtn` → `#cfg` 面板）：判定寬鬆度、
以及「這是怎麼判的」說明。主畫面只剩標題、題目、判定、換一題，其餘留給田字格。
之後要加設定就往那個面板加，不要放回主畫面。

橫式是 `@media (orientation:landscape) and (min-width:760px)`：左欄題目＋判定，右欄田字格。

**橫式的高度瓶頸是左欄不是田字格**（左欄要放題目卡、判定卡、換一題、設定、說明）。
所以田字格放大到某個程度之後，再放大反而是把左欄擠窄、文字換行變多、左欄變更高。
現在的 46vw 上限是在這條線上取的平衡點，不是隨便填的——要再放大就得先讓左欄的內容變少。

畫布解析度跟著實際尺寸走（`fitCanvas()` 的 `k`），格子放大線條才不會糊；
描紅字級由 `fitGhost()` 算。轉向時**兩種監聽都要掛**：`ResizeObserver` 實測在某些
情況不會因為轉向觸發，所以另外掛了 `resize` 和 `orientationchange`。

田字格的座標是用 `getBoundingClientRect` 換算的（`write-demo.html` 的 `xy()`），
`SIZE = 280` 只是內部座標系，**所以格子放多大都行，判定邏輯不用動**。

## 三之四、首頁：選課、選模式、選難易度（2026-08-21 加）

試做頁不再是單頁，變成**首頁 → 練習**兩個畫面（`#home` / `#play`）。

**選課**：年級（1–6）→ 學期 → 課次，資料來自 `data/康軒國語_114學年_逐課彙總.csv`。
課次一次全部攤開、**不要內捲**（清單自己有捲軸會把後面幾課切掉，看不出來還有）。
課次卡是單行的：課名在左、生字數在右，兩欄排列，最多 12 課在直式橫式都放得下。
共 **135 課、2,156 個可出題的字**（`鷸`、`埡` 兩字缺注音或筆順，跳過）。

**題庫**由 `tools/build-write-bank.py` 產生到 `data/write-bank.js`，內嵌進頁面（117 KB）：

```
BANK[字]  = [注音, 教育部總筆畫, 台灣筆順序列, 語詞線索, 部首]
LESSONS[] = [年級, 學期, 課次, 課名, 這一課的生字]
```

**語詞線索只有 84% 的字有**（2156 個裡 344 個沒有）。沒有的改用
「注音＋部首」當線索——只給注音不行，ㄏㄨㄚ 可以是花／華／化／畫。

**三種模式**（`mode`）：

| 模式 | 判什麼 | 難易度有沒有影響 |
|---|---|---|
| `shape` 寫得工整 | 字形＋筆畫數，不看筆順 | 有 |
| `order` 照筆順寫 | 只看每一筆的順序，不管字漂不漂亮 | 沒有（會在說明裡講） |
| `both` 兩個都要（預設） | 兩個都判 | 有 |

`order` 模式仍然要求筆畫數正確——數量不對的話位置對不起來，比了沒意義。

**練習中要換課或換模式**：右上角齒輪 →「← 換一課／換模式」。

## 三之五、獎牌與練習紀錄（2026-08-21 加）

跟 `multiplication.html` 對齊同一套：**9 成金牌、8 成銀牌、7 成銅牌，其餘加油**（`MEDALS`）。

**一課寫完就結算**（`finishRound()`）：顯示獎牌、對幾個字、以及有幾個是大人放行的。
被放行的會另外提醒「那幾個字值得再練一次」。

**頁首改成一排圓鈕**（`.topbar` / `.icobtn`），左邊是課名和進度，右邊是📊練習紀錄和⚙️設定。
沒有做音效鈕。

**練習紀錄**存 `localStorage` 的 `writeDemoRuns`，最多留 20 筆，記課次、模式、對幾題、獎牌、日期。

### ⚠️ 兩個踩過的 CSS 坑

1. `#home` 和 `#play` 在橫式的媒體查詢裡是 `display:grid`，**一定要寫成 `#home:not(.off)`**，
   否則媒體查詢的規則會蓋掉 `.off` 的 `display:none`，畫面藏不起來、兩層疊在一起。
2. 橫式的欄位指定要限定直接子元素（`#play > .card`），不然會誤抓面板裡同名的 class。

## 四、要併進 `chinese.html` 的話

1. 加一個題型 `write`，跟現有的 `ZI_KINDS` 並排（`chinese.html` 的 `KIND_LABEL` 附近）
2. 題目用「注音 + 挖空的語詞」——`itemOf(c)` 裡的 `words` 已經有語詞可以挖
3. 作答畫面換成田字格 canvas，不是四個選項
4. 判對錯用 A 方案的 `compare()`，門檻建議覆蓋率 80%、乾淨度 80%、筆畫數要一致
5. 結果照樣丟進 `logRecent(c, ok)`，熟練度、課的獎牌、首頁的每日獎牌都會自動吃到。
   **被大人放行的要多存一個 `by:'adult'`**——熟練度照算過，但之後可以撈出
   「哪些字是被放行的」，那批字正是最該回頭再練的，比單純的錯題清單準
6. 一輪的題數／秒數要重新想——寫字比選擇題慢很多，20 題大概太多

### 已知還沒解的

- **字型不一定有**：`--abc` 那串楷體在 iOS/Mac 有（BiauKai），Android 常常沒有，
  會退到黑體，比對的標準答案就會是黑體的形狀。要嘛內嵌字型（大）、要嘛偵測不到就
  只給「自己對答案」。**這條沒驗證過，要先測 Android。**
- 小孩寫得很小或很偏的時候，要不要先正規化到田字格再比？現在沒有正規化，
  所以「寫太小」會被判沒寫到。這樣對不對要問家長。
- 沒有處理連筆（兩筆黏在一起畫成一筆）——筆畫數會少 1。
- 題目的難度天花板是「小孩幾年級」。等他學到平方和面積（國小中高年級），這套要再往上調
  （負數、分數運算、百分比之類的）。改 `adultQ()` 一個函式就好。
- **不要再加密碼。** 加了就要各台設定、就會被背起來、好記的數字又通常是個資，
  而這個 repo 是公開的。一道隨機出題的關卡已經同時解掉「通用」和「防偷看」。
