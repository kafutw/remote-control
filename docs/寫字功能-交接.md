# 「看注音寫字」交接文件

要接手的人看這一份就夠。試做頁在 `write-demo.html`，可以直接開：
<https://kafutw.github.io/remote-control/write-demo.html>

---

## 一、這是什麼

`chinese.html`（國語大考驗）現在所有題型都是**四選一**。這個功能要補的是**真的動手寫**——
看注音，在田字格裡用手指把字寫出來。

出題長這樣（**只給注音不行**，ㄏㄨㄚ 可以是 花／華／化／畫，看不出要寫哪個，
所以一定要有語詞當線索）：

```
      ㄏㄨㄚ
      ＿朵
```

## 二、兩種判斷方式，試做都做了

### A. 自動比對（**建議走這條**）

拿**楷體字型畫出來的字當標準答案**，跟小孩寫的線互相比。兩個指標：

| 指標 | 怎麼算 | 抓得到什麼 |
|---|---|---|
| **覆蓋率** | 這個字該有的地方，他寫到了幾成 | 漏筆、寫太小、位置偏掉 |
| **乾淨度** | 他寫的線，有幾成落在這個字上面 | 多寫、寫到格子外面 |

再加一條硬規定：**筆畫數要跟教育部辭典的總筆畫一樣**（`DICT` 裡本來就有，查表即可）。

實測（把標準筆畫餵進去當「寫得很好」，再故意加工）：

| 情況 | 覆蓋率 | 乾淨度 | 抓到了嗎 |
|---|---|---|---|
| 照標準寫 | 89% | 100% | ⭕ 過 |
| 手抖一點 | 91% | 100% | ⭕ 過 |
| **多兩撇**（實際遇到的） | 89% | **89%** | ✗ 乾淨度掉下來 + 筆畫數多 2 |
| 少一筆 | 84% | 100% | ✗ 靠筆畫數抓 |
| 少三筆 | **59%** | 100% | ✗ 覆蓋率直接掉 |
| 整個往右偏 35px | **68%** | 91% | ✗ 覆蓋率掉 |
| 寫成別的字 | 78% | 86% | ✗ 兩個都掉 + 筆畫數不對 |

**成本 0**：字型本來就在裝置上，筆畫數本來就在 `DICT` 裡。不需要任何外部資料。

技術細節（都在 `write-demo.html` 的 `compare()` 附近）：
- 兩張 128×128 的黑白圖，一張是字型填實的字，一張是小孩的線
- 兩趟 chamfer 距離轉換算「離最近的黑點多遠」，容差約 7 格（手寫抖動不計較）
- 128×128 = 16k 像素，手機上跑起來無感

### B. 逐筆對筆順（**入口已從試做頁移除，見第三節**）

每寫一筆就跟正確筆順比：把兩條線都重新取樣成等距 16 點，逐點比距離
（容差 11.5% 格寬），再比方向和長度。錯了會說「第 3 筆方向反了」，
對了就把**標準的那一筆**收進去，所以寫完是漂亮的字。

程式碼可以用（`checkStroke()`、`playOrder()`），**卡在資料**。

> **2026-08-21 更新**：試做頁上「逐筆看筆順」模式和「👀 看筆順」動畫這兩個入口
> 已經拿掉，因為它們會照大陸筆順教。函式和 `STROKES` 都留在檔案裡（有警語注解），
> 拿到台灣標準的資料換掉 `STROKES` 就能接回來。**在那之前不要把入口打開。**

## 三、⚠️ 最重要的一件事：筆順資料的來源不能用

試做用的是 [`skishore/makemeahanzi`](https://github.com/skishore/makemeahanzi)。
拿它的筆畫數跟教育部辭典逐字對，**2,246 個字裡有 276 個對不起來（12.3%）**：

```
差 +1 畫：248 個   差 +2：7 個   差 -1：18 個   差 -2：1 個   差 -3：2 個
例：之 3/4、以 4/5、及 3/4、似 6/7、修 9/10、健 10/11、初 7/8、印 5/6
    花 7/8、草 9/10
```

原因是**那份資料是大陸的筆畫標準**。最典型的是「艹」：大陸算 3 畫、台灣算 4 畫，
所以 花、草 全部差 1。

**後果**：如果照它教筆順，小孩在學校會被算錯，而且會跟 App 自己的
「✏️ 數筆畫」題目打架（那題用的是教育部的數字）——同一個 App 說 草 是 10 畫，
寫字練習卻只讓你寫 9 筆。

**所以：B 方案要做的話，必須先找到台灣標準的筆順資料。**
可以找的方向：教育部《國字標準字體筆順學習網》、《常用國字標準字體筆順手冊》。
找不到就只做 A。

## 三之二、寫錯的時候不給「換一題」（2026-08-21 加）

小孩寫錯只會看到一顆「✏️ 再寫一次」，沒有跳過的按鈕。判定分三檔：

| 檔 | 條件 | 畫面 |
|---|---|---|
| 過 | 覆蓋率 ≥80、乾淨度 ≥80、筆畫數相符 | 出現「換一題」 |
| **差一點** | 只差 1 筆，而且覆蓋率、乾淨度都 ≥70 | 「再寫一次」＋「差一點點」標籤，家長通道那行字轉成琥珀色 |
| 不對 | 其他 | 「再寫一次」，家長通道維持灰色小字 |

**家長／老師通道**：判定卡底下一行小字，點下去跳出面板，先看他寫的字和三個數字，
驗證過了才出現「算他過，下一題」和「不算，讓他重寫」。

驗證預設是**大人會、一年級不會的題目**（`adultQ()`），不用設定、不用記、不用存，
所以**每台裝置行為都一樣**。金鑰是可選的加速選項。三種狀態在 `gateTo()` 裡切換：

| 狀態 | 什麼時候 | 畫面 |
|---|---|---|
| `math` | 預設（沒設過金鑰，或從 pin 點退路過來） | 概念題，答錯換一題新的 |
| `pin` | 有設過金鑰 | 四個圓點，打滿四位自動送出；下面有「忘記金鑰？改用題目 →」 |
| `setpin` | 答對題目而且還沒設過金鑰 | 問要不要設一組；可以按「先不要，這次直接放行」 |

**題庫**（三種，數字每次隨機）：

| 題型 | 例 | 為什麼一年級不會 |
|---|---|---|
| 平方 | `7 的平方是多少？` → 49 | 沒有平方的概念 |
| 面積 | `邊長 8 公分的正方形，面積多少？` → 64 | 沒有面積的概念 |
| 時間換算 | `3 小時是幾分鐘？` → 180 | 要先知道一小時 60 分再乘 |

**為什麼不用純算術**：九九乘法背熟就破了，隔壁 `multiplication.html` 就在練那個。
概念題考的是還沒教到的東西，不是算力。

**為什麼不用分子分母**：答案就印在題目上（問「3/8 的分母」，畫面只有 3 和 8），
亂猜一半會中，跟四選一同一個毛病。

**為什麼數字要隨機**：固定答案的題目（例如「三角形內角和」永遠是 180）
小孩看大人按一次就記住了。

放行區底下有「重設金鑰」，頁面底部另外有一個**「家長設定」**入口
（`openSetup()`，`gateCtx = 'setup'`），不用等小孩寫錯就能先把金鑰設好。

**輸金鑰時鍵盤數字會打亂**（`buildKeypad(true)`），每次開面板重排一次，
這樣小孩在旁邊看，記住的「位置」下次就不管用。⌫ 和「清除」位置固定，不然大人會找不到。
算式模式不打亂——那是要算的、沒有秘密，打亂只是折磨大人。

**為什麼不用選擇題**：四選一又能無限重試，小孩亂點平均四次就過，等於沒鎖。

**為什麼自己畫數字鍵盤**：iPad 橫式叫出系統鍵盤會吃掉大半個畫面，剛調好的版型會被推走。
鍵盤在 `buildKeypad()`，輔助鍵的 class 是 `k-sub`——**不要叫 `sub`**，會被版型的
`body > .sub` 規則抓走，害「清除」掉到第五列（踩過一次）。

**卡關保護**：同一題連錯 3 次，描紅自動打開，家長通道那行字換成
「寫好幾次了？家長／老師可以看一下 →」。還是不給自己跳過。

程式在 `write-demo.html` 的 `openGate()` 一帶，`adultPassed` 陣列先記在記憶體裡。

## 三之三、iPad 橫式版型（2026-08-21 加）

`@media (orientation:landscape) and (min-width:760px)`：左欄放題目和判定結果，
右欄放田字格，田字格從 280px 放大到 330px（`--padsz`），判定結果改成「字在左、話在右」。
1194×790 實測整頁不用捲。

田字格的座標是用 `getBoundingClientRect` 換算的（`write-demo.html` 的 `xy()`），
**所以格子放大只要改 CSS，判定邏輯不用動**。

## 四、要併進 `chinese.html` 的話

1. 加一個題型 `write`，跟現有的 `ZI_KINDS` 並排（`chinese.html` 的 `KIND_LABEL` 附近）
2. 題目用「注音 + 挖空的語詞」——`itemOf(c)` 裡的 `words` 已經有語詞可以挖
3. 作答畫面換成田字格 canvas，不是四個選項
4. 判對錯用 A 方案的 `compare()`，門檻建議覆蓋率 80%、乾淨度 80%、筆畫數要一致
5. 結果照樣丟進 `logRecent(c, ok)`，熟練度、課的獎牌、首頁的每日獎牌都會自動吃到。
   **被大人放行的要多存一個 `by:'adult'`**——熟練度照算過，但之後可以撈出
   「哪些字是被放行的」，那批字正是最該回頭再練的，比單純的錯題清單準
6. 一輪的題數／秒數要重新想——寫字比選擇題慢很多，20 題大概太多

### 已知還沒解的

- **字型不一定有**：`--abc` 那串楷體在 iOS/Mac 有（BiauKai），Android 常常沒有，
  會退到黑體，比對的標準答案就會是黑體的形狀。要嘛內嵌字型（大）、要嘛偵測不到就
  只給「自己對答案」。**這條沒驗證過，要先測 Android。**
- 小孩寫得很小或很偏的時候，要不要先正規化到田字格再比？現在沒有正規化，
  所以「寫太小」會被判沒寫到。這樣對不對要問家長。
- 沒有處理連筆（兩筆黏在一起畫成一筆）——筆畫數會少 1。
- 金鑰仍可能被偷看：鍵盤打亂擋掉的是「記位置」，小孩要是**盯著看數字**還是記得住。
  概念題沒這個問題（數字每次都換），所以不設金鑰其實比較安全，金鑰只是圖快。
- **不要把預設金鑰寫死在原始碼裡**。這個 repo 是公開的，寫進去等於公開；
  而且好記的數字通常是個資（門牌、電話末四碼、紀念日）。
  「所有裝置通用」這件事已經由概念題解決了，不需要通用金鑰。
- 概念題的難度天花板是「小孩幾年級」。等他學到平方和面積（國小中高年級），這套要再往上調。
- 「忘記金鑰？改用算式」這條退路，等於算式那道門一直都在。小孩要是背熟九九乘法又會拆算式，
  這條就是破口。真的被破解再考慮拿掉退路、改成別的重設方式。

所以檔案變大是每次開都要付的成本。真要做，建議**只載入選到那一課的字**
（一課 16 個字約 7 KB），不要整包塞進去。
